# Наизусть — приложение для заучивания текстов

React + TypeScript + Vite, данные хранятся локально (IndexedDB через Dexie).

## Запуск
```
npm install
npm run dev      # разработка
npm test         # тесты логики прогресса
npm run build    # сборка в dist/
```

## Структура
- `src/logic/config.ts` — все числа: интервалы, пороги очков, очки за упражнения. Меняйте здесь.
- `src/logic/progress.ts` — очки, уровни, условия повышения и понижения (чистые функции, покрыты тестами).
- `src/logic/stats.ts` — серия дней, очки по дням, точность (чистые функции, покрыты тестами).
- `src/logic/parser.ts` — разбор текста на строки и слова.
- `src/exercises/` — упражнения (готовы все 9). Новое упражнение: компонент + запись в `index.ts` + `implemented: true` в `config.ts`.
- `src/exercises/useWordTyper.ts`, `TypedText.tsx` — общий ввод слов для «Ввода текста целиком», «Продолжи строку» и «Допиши конец строки».
- `src/logic/exercises.ts` — генерация заданий (пропуски, блоки, маски) — чистые функции, покрыты тестами.
- `src/pages/` — экраны: «Сегодня» (что повторить и что предложено сделать), «Тексты», страница текста, упражнение.
- `src/db/db.ts` — локальная база (Dexie): хуки, которые помечают изменённые записи для синхронизации, экспорт/импорт/очистка.
- `src/sync/` — облако: `client.ts` (Supabase), `sync.ts` (цикл синхронизации), `mapping.ts` (преобразования и правило слияния, покрыто тестами), `SyncProvider.tsx` (вход и автосинхронизация).
- `supabase/schema.sql` — таблицы и правила доступа для облака.
- `src/logic/backup.ts` — формат и проверка файла резервной копии (покрыто тестами).

## Бесплатный хостинг
Сборка статическая (HashRouter, `base: './'`), подойдёт GitHub Pages, Cloudflare Pages или Netlify:
команда сборки `npm run build`, папка публикации `dist`.

## Установка на телефон (PWA)
После публикации на HTTPS-хостинге приложение можно установить и использовать офлайн:
- Android (Chrome): меню ⋮ → «Установить приложение» / «Добавить на главный экран».
- iPhone (Safari): «Поделиться» → «На экран «Домой»».

Обновления подхватываются автоматически: после выхода новой версии она применяется при следующем открытии.
Service worker работает только на HTTPS (и на localhost), в `npm run dev` он по умолчанию не включён;
проверить PWA локально можно так: `npm run build && npm run preview`.

## Резервные копии
Данные хранятся только в браузере. Страница «Данные» (значок ⚙ в шапке) позволяет скачать копию в JSON
и восстановить её: заменить текущие данные или добавить к ним. Раз в 14 дней на экране «Сегодня» появляется напоминание.

## Облачная синхронизация (Supabase, необязательно)
Без настройки приложение работает полностью локально. Чтобы тексты и прогресс синхронизировались между устройствами:

1. Создайте бесплатный проект на supabase.com.
2. В **SQL Editor** выполните целиком файл `supabase/schema.sql` (таблицы, триггеры, правила доступа RLS).
3. **Authentication → Providers → Email**: отключите **Confirm email**. Тогда вход работает по почте и паролю без писем
   (встроенная отправка писем в бесплатном тарифе сильно ограничена). Любой адрес можно указать без подтверждения,
   но это влияет только на вход в собственный аккаунт: чужие данные недоступны благодаря RLS.
4. **Project Settings → API**: скопируйте Project URL и anon public key в файл `.env`
   (образец: `.env.example`). На хостинге добавьте те же две переменные в настройки сборки
   (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`) и пересоберите проект.
5. В приложении: ⚙ → «Облако» → создайте аккаунт или войдите.

Как это работает:
- Локальная база остаётся основной: всё работает без сети, изменения отправляются, когда она появится.
- Синхронизация запускается после входа, через несколько секунд после изменений, при возвращении в приложение и вручную.
- Тексты сливаются по правилу «побеждает более новое изменение», попытки только добавляются.
- Удаление текста распространяется на другие устройства. При выходе данные остаются на устройстве;
  при входе под другим аккаунтом приложение предложит удалить данные предыдущего.
- Бесплатные проекты Supabase «засыпают» после недели без активности. Данные не пропадают, проект включается кнопкой в панели.
- Если у вас уже есть данные на устройстве и в облаке, при первом входе они объединяются. Один и тот же текст,
  созданный независимо на двух устройствах, останется в двух экземплярах.

## Текст Библии (Синодальный перевод)
Текст не лежит в репозитории, его нужно один раз подготовить:

```
npm run bible:build
```

Скрипт скачивает Синодальный перевод (формат Zefania XML, общественное достояние), проверяет, что в нём 66 книг и нет пустых глав,
и записывает `public/bible/rst/index.json` и по файлу на каждую книгу. Если скачивание не удалось, скачайте файл вручную и укажите путь:
`npm run bible:build -- --file rus-synodal.zefania.xml` (адрес можно поменять через `--url`).
Скрипт печатает отчёт: число глав и стихов по книгам и предупреждения (например, пропущенные стихи). Результат нужно закоммитить:
при сборке на хостинге скрипт не запускается. Книги загружаются по мере открытия и кэшируются для работы офлайн.

Псалтирь: в источнике псалмы пронумерованы по-еврейски, а в Синодальном издании по славянской нумерации (как в Септуагинте).
Скрипт приводит её к синодальной: псалмы 9 и 10 объединяются в 9-й, 114 и 115 в 113-й, 116-й делится на 114-й и 115-й,
147-й на 146-й и 147-й, остальные с 11-го по 146-й сдвигаются на единицу; ссылки в скобках перед стихами, например «(9:22)», убираются.
Если число стихов в источнике окажется другим, правка не применяется, а в отчёте появляется предупреждение.

Структура: `src/bible/books.json` — список 66 книг в порядке Синодального издания; `src/bible/refs.ts` — ключи стихов, сортировка,
склейка соседних стихов в диапазоны; `src/bible/bible.ts` — загрузка текста; `scripts/zefania.mjs` — разбор и проверка источника.

## Запоминание стихов
У стиха две независимые характеристики (`src/logic/mastery.ts`).

**Сила (0–6)** показывает, насколько хорошо стих знают сейчас: 0 — новый, 1–2 — начал учить, 3–4 — средне, 5–6 — твёрдо.
- Растёт на 1 за каждое успешное упражнение (90% и выше), если оно достаточно сложное: узнавание поднимает до 2,
  вспоминание с опорой — до 4, ввод по памяти — выше. Ограничения «раз в день» нет: за один день можно подняться до максимума.
- Ошибка (ниже 70%) снижает силу на 1 (ниже 40% — на 2), но не ниже 1. Результат 70–89% силу не меняет.
- Сила определяет, какие упражнения и какой сложности достаются стиху.

**Стадия повторения (0–6)** задаёт расписание: повторять через 1, 3, 7, 14, 30 и 60 дней.
- Первый зачёт нового стиха ставит его на стадию 1 (повтор через день).
- Зачёт в назначенный срок (достаточно сложным упражнением) переводит на следующую стадию. До зачёта стих остаётся «к повторению».
- Ошибка в срок снижает стадию и возвращает стих на завтра. Ошибка до срока стадию не меняет, но стих вернётся не позже чем через день.
- В день повторения стиху достаётся больше упражнений в уроке.

Каждый результат пишется в журнал (`reviews`) вместе с очками опыта. Стихи и журнал синхронизируются с облаком.

## Уроки по стихам
Кнопка «Начать урок» (на экранах «Сегодня» и «Стихи») собирает урок из ваших стихов: до двух новых, затем те, что пора повторять
или где недавно была ошибка (`src/lessons/generator.ts`). Урок состоит из упражнений: открытие по тапу, частично скрытый текст
(два ползунка) и выбор пропущенных слов. Вверху прогрессбар, после ответа — «Верно» или «Есть ошибки».
Упражнения с ошибками повторяются в конце урока. Учебные упражнения (открытие и скрытый текст) силу стиха не меняют.
У нового стиха после знакомства идут три несложных упражнения в случайном порядке (пропуски, сборка из 4 частей, «где написано» по книге).

Упражнения, которые проверяют стих и влияют на его силу (`stepTier` в `src/lessons/types.ts`):
- «Первые буквы» с тремя уровнями: слова видны целиком — 1; видны примерно половина — 2; видны только пробелы — 2;
- ввод по памяти: если часть слов уже стоит на месте — 2, с чистого листа — 3;
- выбор пропущенных слов — сложность 1;
- «Где написано» (книга; книга и глава; книга, глава и стих) — 1, а с вопросом про стих — 2;
- «Соберите стих» (слова и фразы, перетаскивание или нажатия) — 1 для коротких, иначе 2;
- «Расставьте части по порядку» (несколько стихов подряд без номеров до проверки) — 2.

Для стиха выбирается одно дополнительное упражнение и «главное»: то, чьей сложности достаточно для роста силы.
Рост силы выше 4 требует упражнения без подсказок (ввод по памяти): оно есть в тестовом уроке.

## Путь уроков (главный экран)
Главный экран «Сегодня» показывает путь: последние пройденные уроки, текущий и несколько будущих. Нажатие на пройденный урок
открывает карточку (опыт, ошибки, стихи) и кнопку «Повторить урок». Текущий можно начать или пропустить.
Типы уроков (`src/lessons/generator.ts`):
- **Обычный** — до двух новых стихов и повторение недавних.
- **Закрепление** — только уже начатые стихи. Чаще попадаются те, где была ошибка, которые пора повторять или которые недавно начали учить; твёрдо выученные реже.
- **Тест** — одно задание: ввести стих (до трёх подряд) по памяти. Нет прогрессбара и повторов ошибок. Нужны стихи с силой не ниже 2.
  Чем слабее стих, тем больше слов подсказано: сила 2 — показано 60% слов, сила 3 — 35%, с силы 4 — чистый лист.

Порядок на пути: обычный, обычный, закрепление, обычный, тест, и дальше по кругу. Если провести урок нужного типа нельзя
(например, нет новых стихов или выученных для теста), он заменяется подходящим. Состав урока собирается, когда его начинают.
История уроков синхронизируется с облаком (после обновления выполните `supabase/schema.sql` ещё раз).

## Порядок стихов в больших отрывках
Новые стихи вводятся строго по порядку Библии (до двух за урок). К ним добавляются стихи по соседству, которым пора повторяться или
где была ошибка (`pickVerses` в `src/lessons/generator.ts`). В уроках закрепления выбирается опорный стих, а остальные подбираются так,
что вероятность быстро падает с расстоянием до него (`pickReviewVerses`). Строго по очереди отрывок не идёт: в уроке стихи и упражнения перемешаны.

## Вопрос «Где написано»
Если ответом на последние вопросы подряд была та же книга, вопрос по этой книге предлагается всё реже и после трёх одинаковых ответов
не предлагается вовсе, пока не сменится книга (`shouldSkipWhere`). Недавние ответы берутся из журнала результатов.

## Вкладка «Стихи» («Мои стихи»)
Стихи делятся по твёрдости: «Новые» (сила 0), «Начал учить» (1–2), «Средне» (3–4), «Твёрдо» (5–6). Вверху фильтры по группам с числом стихов.
Строки идут в порядке Библии, соседние стихи одной главы и одной твёрдости склеены в диапазон (`src/logic/library.ts`);
стихи разных глав и книг, а также соседние стихи с разной твёрдостью в одну строку не попадают. У строки видны сила (шесть точек),
срок повторения и начало текста.

## Профиль
Значок ⚙ ведёт на страницу «Профиль и данные». При регистрации по почте нужно указать имя; позже его можно изменить там же
(«Изменить имя»). Имя хранится в данных аккаунта Supabase, отдельная таблица и дополнительный SQL не нужны.
На странице профиля видны ваш опыт и число пройденных уроков. Если на устройстве остались данные другого аккаунта,
при входе приложение предложит их удалить.
